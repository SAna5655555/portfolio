# Интеллектуальный Ассистент Инженера  
**Платформа для автоматизации технической поддержки промышленного оборудования**

---

## О проекте

В крупной нефтегазовой компании с 50 производственными площадками и 145 000+ единиц оборудования инженеры ежедневно сталкиваются с отказами приборов и систем автоматизации. Проблема в том, что накопленный опыт решения подобных задач не структурирован и не используется системно.

**Мной была разработана платформа, которая:**

- Анализирует корпоративные чаты инженеров в реальном времени.
- Автоматически извлекает инциденты из переписки.
- Ведёт базу знаний всех произошедших событий.
- По запросу инженера выдаёт готовые решения на основе прошлого опыта.
- Предоставляет аналитику отказов в привязке к каждой единице оборудования.

---

## Проблема

| Что было | Что это значило для бизнеса |
|---|---|
| Инженеры тратили часы на поиск решения похожей проблемы вручную | Простои оборудования, потеря денег |
| Опыт уходил вместе с сотрудниками | Компания теряла знания, а не сотрудников |
| Статистика отказов не велась в привязке к оборудованию | Было сложнее оценивать надёжность разных марок и поставщиков |
| Инженеры отвлекались на рутину | Снижение общей эффективности команды |

---

## Решение

Я разработал архитектуру, которая объединяет:

| Компонент | Что делает |
|---|---|
| **Коннектор к мессенджеру** | Читает чаты инженеров в реальном времени, извлекает инциденты |
| **База знаний инцидентов** | Хранит все события с полной историей |
| **Справочник оборудования (CMDB)** | 145 000+ единиц оборудования с иерархией |
| **Семантический поиск (RAG)** | Находит похожие случаи по смыслу, а не по ключевым словам |
| **Генерация ответов (LLM)** | Выдаёт готовые решения на основе прошлого опыта |
| **Веб-интерфейс администратора** | Дашборды, аналитика, управление |
| **Аналитика** | Топ-10 отказов, динамика, MTTR |

---

## Как это работает на практике

1. Инженер описывает проблему в корпоративном чате.
2. Система распознаёт, что это инцидент, и извлекает тег оборудования.
3. Мгновенно ищет похожие случаи по смыслу (не по ключевым словам).
4. Выдаёт готовое решение с ссылкой на прошлый инцидент.
5. Инженер закрывает проблему — и этот случай остаётся в базе знаний навсегда.

**Результат:** то, что раньше занимало часы, теперь занимает несколько минут. Опыт больше не теряется, каждое решение сохраняется и становится доступным для всей компании.

## Технологии

| Категория | Использованные технологии |
|---|---|
| **Бэкенд** | Python 3.12, FastAPI, Uvicorn |
| **Базы данных** | PostgreSQL (структура), Qdrant (векторный поиск) |
| **ИИ / ML** | DeepSeek V4 Flash (LLM), sentence-transformers (эмбеддинги), RAG |
| **Интеграции** | API Яндекс Мессенджера (Webhook) |
| **Инфраструктура** | Docker, Docker Compose |
| **Фронтенд админки** | Jinja2, Bootstrap 5, Plotly |
